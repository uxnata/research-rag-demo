# RAG-ассистент по отчетам ЦБ РФ

Система вопросов и ответов по ежемесячным отчетам Центрального банка РФ «О развитии банковского сектора». Построена на RAG (Retrieval-Augmented Generation) — подходе, при котором языковая модель отвечает не из «головы», а на основе конкретных документов, с указанием источников.

## Что делает

На вход — вопрос на русском языке. На выход — ответ с точными цифрами и ссылками на конкретную страницу конкретного отчета.

**Пример:**

```
Вопрос: Что происходило с прибылью банков в 2025 году?

Ответ: В первом полугодии 2025 года прибыль банков росла: в мае
чистая прибыль составила 296 млрд руб., в июне выросла до 392 млрд руб.
Во втором полугодии произошло снижение: в сентябре — 367 млрд руб.,
в октябре упала до 310 млрд руб.
[Источник: razv_bs_25_05.pdf, стр. 12; razv_bs_25_06.pdf, стр. 11]
```

Без RAG та же модель на тот же вопрос выдает общие слова без цифр и источников. С RAG — проверяемые факты.

## Зачем это нужно

Исследовательские отчеты накапливаются, но не переиспользуются. ЦБ публикует «О развитии банковского сектора» каждый месяц — 22 страницы цифр, графиков, аналитических буллетов. За год — 264 страницы. Искать нужную цифру по PDF вручную — нереалистично. Этот инструмент превращает корпус отчетов в базу знаний, которая отвечает на вопросы.

## Как работает RAG

RAG (Retrieval-Augmented Generation) — подход из пяти шагов:

```
Вопрос пользователя
        |
        v
  [1. Эмбеддинг]           Вопрос превращается в вектор (массив из 768 чисел)
        |
        v
  [2. Поиск + Re-ranker]   Qdrant находит 20 кандидатов, русский re-ranker
        |                   отбирает лучшие 5
        v
  [3. Генерация]            GigaChat формирует ответ строго по фрагментам
        |
        v
  [4. Верификация]          YandexGPT проверяет каждую цифру в ответе —
        |                   неподтвержденные контекстом удаляются
        v
  Проверенный ответ с цитатами
```

Шаг 4 (Corrective RAG) — ключевое отличие от стандартного RAG. Отдельная модель проверяет ответ генератора, удаляя галлюцинации до того, как они дойдут до пользователя.

## Технологический стек

Весь стек — российский или open-source. Ни одного API за пределами РФ.

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| Векторная БД | Qdrant (локально) | Хранит вектора чанков, ищет похожие. Российская команда, open-source |
| Эмбеддинги | sergeyzh/LaBSE-ru-turbo (500 МБ) | Превращает текст в вектор. Заточена под русский |
| Re-ranker | DiTy/cross-encoder-russian-msmarco | Русскоязычный re-ranker на основе DeepPavlov/rubert-base-cased |
| Генерация | GigaChat Pro (Сбер) | Формирует ответ по найденным фрагментам |
| Верификация | YandexGPT | Проверяет ответ GigaChat — удаляет неподтвержденные утверждения |
| Парсинг PDF | pypdf | Извлекает текст из PDF-отчетов ЦБ |
| Скрейпинг | requests + BeautifulSoup | Скачивает отчеты с сайта ЦБ |
| Демо-интерфейс | Gradio | Веб-интерфейс с чатом |

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone https://github.com/uxnata/research-rag-demo.git
cd research-rag-demo
```

### 2. Создать окружение

```bash
conda env create -f environment.yml
conda activate research-rag
```

### 3. Получить API-ключи

Нужны два ключа:

**GigaChat (Сбер)** — для генерации ответов:
- Зайти на [developers.sber.ru/studio](https://developers.sber.ru/studio) через Сбер ID
- Создать проект → GigaChat API → получить Authorization key
- Минимальный пакет GigaChat Pro: 1 500 ₽ за 3 млн токенов

**YandexGPT** — для верификации ответов и эвалуации:
- Зайти на [console.yandex.cloud](https://console.yandex.cloud)
- Создать сервисный аккаунт → API-ключ
- Есть стартовый грант

### 4. Настроить ключи

```bash
cp .env.example .env
```

Открыть `.env` и вставить ключи:

```
GIGACHAT_CREDENTIALS=ваш_ключ_gigachat
YANDEX_API_KEY=ваш_ключ_yandex
YANDEX_FOLDER_ID=ваш_folder_id
```

### 5. Проверить подключение

```bash
python src/generation/test_gigachat.py
```

### 6. Скачать отчеты ЦБ

```bash
python src/ingestion/scraper_cbr.py
```

Скачает все доступные PDF с сайта ЦБ (~87 файлов). Повторный запуск скачает только новые.

### 7. Подготовить чанки

```bash
python src/ingestion/chunker.py
```

Разрежет PDF на фрагменты, отфильтрует мусор от графиков, глоссарий и примечания.

### 8. Проиндексировать

```bash
python src/indexing/indexer.py
```

Первый запуск скачает модели эмбеддингов (~500 МБ) и re-ranker'а (~2 ГБ).

### 9. Задать вопрос

```bash
# Один вопрос
python src/retrieval/rag_pipeline.py "Какова прибыль банковского сектора?"

# Интерактивный режим
python src/retrieval/rag_pipeline.py
```

### 10. Запустить веб-интерфейс

```bash
python app/gradio_app.py
```

Открыть в браузере: `http://localhost:7860`

## Автообновление

При выходе нового отчета ЦБ — одна команда:

```bash
python -m src.ingestion.update
```

## Эвалуация

Тест-сет из 15 вопросов. Генерирует ответы GigaChat, оценивает YandexGPT (перекрестная оценка моделями).

```bash
python src/evaluation/evaluate.py
```

### Финальные метрики (вопросы в рамках корпуса, 11 шт.)

| Метрика | Значение | Что измеряет |
|---------|---------|-------------|
| Достоверность (Faithfulness) | **0.80** | Доля утверждений в ответе, подтвержденных контекстом |
| Релевантность ответа (Relevancy) | **0.86** | Насколько ответ соответствует вопросу |
| Точность поиска (Context Precision) | **0.73** | Доля найденных чанков из правильных источников |
| Хорошие ответы | **9 из 11** | Вопросы с faithfulness ≥ 0.7 |

### Что дало рост метрик

| Улучшение | Эффект |
|-----------|--------|
| Чистка чанков (глоссарий, примечания, подписи к графикам) | Precision: 0.48 → 0.73 |
| Русский re-ranker вместо английского | Корректный поиск синонимов («вклады» = «средства физлиц») |
| Самопроверка в промпте | Модель проверяет цифры перед включением в ответ |
| Corrective RAG (YandexGPT верификация) | Достоверность: 0.69 → 0.80, удаление галлюцинаций |

### Калибровка судьи

Первый прогон дал faithfulness 0.41. После анализа — проблема в промпте YandexGPT-судьи: модель считала «0,4 трлн руб.» и «0.4 трлн рублей» несовпадением. После калибровки — корректные оценки.

## Известные ограничения

- **Таблицы из PDF** — pypdf плохо извлекает табличные данные. Информация о ключевой ставке в таблицах не попадает в чанки корректно
- **Дисперсия метрик** — два прогона дают разброс ±0.15, потому что и генератор, и судья недетерминированы
- **Один источник** — только отчеты «О развитии банковского сектора». Вопросы за пределами этого корпуса получают честный отказ
- **Железо** — прототип собран на MacBook M1 8 ГБ RAM. Модели подбирались под это ограничение

## Возможные улучшения

- **Гибридный поиск** — BM25 + вектор для точного совпадения ключевых слов
- **Семантическое разбиение** — разбивка по смыслу вместо разбивки по страницам
- **Анализ структуры страницы** — парсинг PDF с пониманием структуры страницы вместо pypdf
- **Расширение корпуса** — пресс-релизы ЦБ, обзоры финансовой стабильности, доклады о ДКП
- **Локальное развертывание** — GigaChat заменяется на локальную модель, весь стек работает офлайн
