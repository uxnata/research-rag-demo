# RAG-ассистент по отчетам ЦБ РФ

Система вопросов и ответов по ежемесячным отчетам Центрального банка РФ «О развитии банковского сектора». Построена на RAG (Retrieval-Augmented Generation) — подходе, при котором языковая модель отвечает не из «головы», а на основе конкретных документов, с указанием источников.

## Что делает

На вход — вопрос на русском языке. На выход — ответ с точными цифрами и ссылками на конкретную страницу конкретного отчета.

**Пример:**

```
Вопрос: Что происходило с прибылью банков в 2025 году?

Ответ: В первом полугодии 2025 года прибыль банков росла: в мае
чистая прибыль составила 296 млрд руб., в июне выросла до 392 млрд руб.
Во втором полугодии произошло снижение: в сентябре — 367 млрд руб.,
в октябре упала до 310 млрд руб.
[Источник: razv_bs_25_05.pdf, стр. 12; razv_bs_25_06.pdf, стр. 11]
```

Без RAG та же модель на тот же вопрос выдает общие слова без цифр и источников. С RAG — проверяемые факты.

## Зачем это нужно

Исследовательские отчеты накапливаются, но не переиспользуются. ЦБ публикует «О развитии банковского сектора» каждый месяц — 22 страницы цифр, графиков, аналитических буллетов. За год — 264 страницы. Искать нужную цифру по PDF вручную — нереалистично. Этот инструмент превращает корпус отчетов в базу знаний, которая отвечает на вопросы.

## Как работает RAG

RAG (Retrieval-Augmented Generation) — подход из четырех шагов:

```
Вопрос пользователя
        |
        v
  [1. Эмбеддинг]         Вопрос превращается в вектор (массив из 768 чисел),
        |                 который отражает смысл вопроса
        v
  [2. Поиск]              Qdrant ищет в базе чанки с похожими векторами.
        |                 Re-ranker переранжирует кандидатов для точности
        v
  [3. Сборка промпта]     Найденные фрагменты + вопрос + инструкция
        |                 собираются в один промпт для LLM
        v
  [4. Генерация]          GigaChat читает фрагменты и формирует ответ
        |                 строго на их основе, с указанием источников
        v
  Ответ с цитатами
```

Ключевая идея: модель не выдумывает — она пересказывает то, что нашел поисковик, и указывает откуда взяла каждый факт.

## Технологический стек

Весь стек — российский или open-source. Ни одного API за пределами РФ.

| Компонент | Технология | Зачем |
|-----------|-----------|-------|
| Векторная БД | Qdrant (локально) | Хранит вектора чанков, ищет похожие. Российская команда, open-source |
| Эмбеддинги | sergeyzh/LaBSE-ru-turbo | Превращает текст в вектор. 500 МБ, заточена под русский |
| Re-ranker | cross-encoder/ms-marco-MiniLM-L-6-v2 | Переранжирует результаты поиска для точности. 80 МБ |
| Генерация | GigaChat Pro (Сбер) | Формирует ответ по найденным фрагментам |
| Оценка качества | YandexGPT | Независимый судья — оценивает ответы GigaChat |
| Парсинг PDF | pypdf | Извлекает текст из PDF-отчетов ЦБ |
| Скрейпинг | requests + BeautifulSoup | Скачивает отчеты с сайта ЦБ |
| Демо-интерфейс | Gradio | Веб-интерфейс с чатом |

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone https://github.com/uxnata/research-rag-demo.git
cd research-rag-demo
```

### 2. Создать окружение

```bash
conda env create -f environment.yml
conda activate research-rag
```

### 3. Получить API-ключи

Нужны два ключа:

**GigaChat (Сбер)** — для генерации ответов:
- Зайти на [developers.sber.ru/studio](https://developers.sber.ru/studio) через Сбер ID
- Создать проект → GigaChat API → получить Authorization key
- Минимальный пакет GigaChat Pro: 1 500 ₽ за 3 млн токенов

**YandexGPT** — для эвалуации (опционально):
- Зайти на [console.yandex.cloud](https://console.yandex.cloud)
- Создать сервисный аккаунт → API-ключ
- Есть стартовый грант

### 4. Настроить ключи

```bash
cp .env.example .env
```

Открыть `.env` и вставить ключи:

```
GIGACHAT_CREDENTIALS=ваш_ключ_gigachat
YANDEX_API_KEY=ваш_ключ_yandex
YANDEX_FOLDER_ID=ваш_folder_id
```

### 5. Проверить подключение

```bash
python src/generation/test_gigachat.py
```

Если в ответе — текст от GigaChat, все настроено.

### 6. Скачать отчеты ЦБ

```bash
python src/ingestion/scraper_cbr.py
```

Скачает все доступные PDF с сайта ЦБ (~87 файлов). Повторный запуск скачает только новые.

### 7. Подготовить чанки

```bash
python src/ingestion/chunker.py
```

Разрежет PDF на фрагменты, отфильтрует мусор от графиков, сохранит в `data/processed/chunks.json`.

### 8. Проиндексировать

```bash
python src/indexing/indexer.py
```

Первый запуск скачает модель эмбеддингов (~500 МБ). Превратит чанки в вектора и загрузит в Qdrant.

### 9. Задать вопрос

```bash
# Один вопрос
python src/retrieval/rag_pipeline.py "Какова прибыль банковского сектора?"

# Интерактивный режим
python src/retrieval/rag_pipeline.py
```

### 10. Запустить веб-интерфейс

```bash
python app/gradio_app.py
```

Открыть в браузере: `http://localhost:7860`

## Автообновление

При выходе нового отчета ЦБ — одна команда:

```bash
python -m src.ingestion.update
```

Скрипт проверит сайт ЦБ, скачает новые PDF, прочанкует, проиндексирует. Уже проиндексированные файлы не трогает.

## Эвалуация

Система оценивается по трем метрикам. Генерирует ответы GigaChat, оценивает YandexGPT (cross-model evaluation — независимая оценка другой моделью).

```bash
python src/evaluation/evaluate.py
```

### Метрики

| Метрика | Значение | Что измеряет |
|---------|---------|-------------|
| Faithfulness | 0.84 | Доля утверждений в ответе, подтвержденных контекстом. 1.0 = все факты из документов |
| Answer Relevancy | 0.88 | Насколько ответ соответствует вопросу. 1.0 = точно по теме |
| Context Precision | 0.48 | Доля найденных чанков из правильных источников. 1.0 = все чанки релевантны |

### Интерпретация

- **Faithfulness 0.84** — система редко галлюцинирует. 84% фактов в ответах подтверждены документами
- **Relevancy 0.88** — система почти всегда отвечает по делу
- **Context Precision 0.48** — главный bottleneck. Retriever в половине случаев находит не самые релевантные чанки. Re-ranker частично решает проблему, но для кардинального улучшения нужен гибридный поиск (вектор + BM25)

### Калибровка судьи

Первый прогон дал faithfulness 0.41. После анализа — проблема оказалась в промпте YandexGPT-судьи: модель интерпретировала «подтверждается контекстом» буквально и считала «0,4 трлн руб.» и «0.4 трлн рублей» несовпадением. После калибровки промпта — 0.84. Подробности — в `docs/article.md`.

## Известные ограничения

- **Таблицы из PDF** — pypdf плохо извлекает табличные данные. Информация о ключевой ставке хранится в таблицах и не попадает в чанки корректно
- **Дисперсия метрик** — два прогона дают разброс ±0.15–0.20, потому что и генератор, и судья недетерминированы. Для надежной оценки — усреднение по 3–5 прогонам
- **Железо** — прототип собран на MacBook M1 8 ГБ RAM. Модели подбирались под это ограничение. На сервере с GPU можно использовать более тяжелые модели (bge-m3, bge-reranker-v2-m3)
- **Один источник** — только отчеты «О развитии банковского сектора». Вопросы за пределами этого корпуса получают честный отказ

## Возможные улучшения

- **Гибридный поиск** — BM25 + вектор для точного совпадения ключевых слов
- **Semantic chunking** — разбивка по смыслу вместо разбивки по страницам
- **Layout analysis** — парсинг PDF с пониманием структуры страницы вместо pypdf
- **Расширение корпуса** — пресс-релизы ЦБ, обзоры финансовой стабильности, доклады о ДКП
- **On-prem** — GigaChat заменяется на локальную модель (Qwen 3B), весь стек работает офлайн
