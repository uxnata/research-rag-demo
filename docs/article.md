# RAG по отчетам ЦБ: как собрать ресерч-ассистента

Исследовательские отчеты накапливаются. ЦБ выпускает «О развитии банковского сектора» каждый месяц — 22 страницы цифр, графиков, аналитических буллетов. За год — 264 страницы. За три — почти 800. Кто-нибудь это переиспользует? Нет. Новый ресерчер приходит и пишет все с нуля, потому что искать по PDF вручную — невозможно.

Решение — RAG-ассистент. Вопрос на русском → ответ с точными цифрами и ссылкой на конкретную страницу конкретного отчета. Вот реальный пример из системы:

> **Вопрос:** Что происходило с прибылью банков в 2025 году?
>
> **Ответ:** В первом полугодии 2025 года прибыль банков росла: в мае чистая прибыль составила 296 млрд руб., в июне выросла до 392 млрд руб. Во втором полугодии произошло снижение: в сентябре — 367 млрд руб., в октябре упала до 310 млрд руб. [Источник: razv_bs_25_05.pdf, стр. 12; razv_bs_25_06.pdf, стр. 11]

Не галлюцинации — проверяемые факты с адресом в документе. А теперь — как это собрано, какие проблемы встретились и что из этого можно переиспользовать.

## Стек: все в российском периметре

Ни одного API за пределами РФ. Что под капотом:

- **Qdrant** — векторная база, локально, без Docker, без облака. Российская команда, open-source. Один нюанс: на машине с 8 ГБ RAM Docker съедает ~500 МБ на контейнер. Qdrant умеет работать в локальный режим — прямо из Python, данные в папке на диске: `QdrantClient(path="data/qdrant_db")`. Экономия памяти, ноль настройки
- **Эмбеддинги** — `sergeyzh/LaBSE-ru-turbo`, 500 МБ. Изначально в плане стояла `deepvk/USER-bge-m3` (2.2 ГБ, размерность 1024) — не влезла на диск. LaBSE-ru-turbo дает размерность 768, для прототипа разница в качестве минимальна, а по ресурсам — в 4 раза легче
- **Генерация** — GigaChat Pro от Сбера. Минимальный пакет: 3 миллиона токенов за 1 500 ₽. Расчет: один RAG-запрос ≈ 4 000 токенов (промпт 300 + вопрос 50 + контекст 3 000 + ответ 500). Итого 3 млн токенов = 750 запросов. На тест-сет из 15 вопросов, отладку промптов и демо — хватило с запасом
- **Верификация и оценка** — YandexGPT как независимый судья и верификатор. Генерирует одна модель, проверяет и оценивает другая — перекрестная оценка двумя моделями

## Скрейпинг: 87 отчетов, одна команда

Скрейпер заходит на cbr.ru, парсит страницу через BeautifulSoup, скачивает PDF. 87 отчетов с 2018 года — один запуск.

Первый баг: ЦБ возвращал 403 Forbidden начиная со второго файла. Первый скачивался, остальные — нет. Причина — сервер проверяет заголовок `Referer` и cookies. Без них считает запрос «чужим».

Решение заняло две строки:

```python
session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 ...",
    "Referer": "https://cbr.ru/analytics/bank_sector/develop/",
})
```

`requests.Session()` сохраняет cookies между запросами (как браузер), `Referer` говорит серверу «запрос пришел с вашей страницы». После этого — 87 из 87, ноль ошибок.

Практический совет: в скрейпере есть проверка `if filepath.exists(): пропускаю`. При повторном запуске скачиваются только новые файлы. Автообновление — одна команда: `python -m src.ingestion.update`.

## Чанкинг: три итерации, каждая критична

Это самая недооцененная часть RAG. Качество чанкинга определяет качество всего пайплайна. Три итерации, каждая поднимала метрики.

### Итерация 1: наивная

Разведка данных показала, что `pypdf` вытаскивает из PDF ЦБ смесь полезного текста и мусора:

```
DEFGHIJKLM           ← обрывки шрифтов из SVG-графиков
bcdefghijk            ← то же самое
15,5% 12,5% 12,4%    ← числа с осей диаграмм
N U Y                 ← элементы легенды
• Рост требований к компаниям в марте составил 0,5 трлн руб.  ← ЗОЛОТО
```

Первый фильтр — оставлять только строки с русскими буквами (минимум 3) и буллеты (•). Это убрало `DEFGHIJKLM` и числовой мусор, но пропустило подписи к графикам на русском: «Сноски для текста», «Прирост за месяц», «трлн руб.».

### Итерация 2: паттерны мусора

Добавлен список известных мусорных паттернов — 15 строк, собранных вручную при просмотре чанков:

```python
JUNK_PATTERNS = [
    "Сноски для текста",
    "Сноски для таблиц",
    "Значения приведены на конец месяца",
    "Источник: ф.о.",
    "Прирост за месяц",
    "трлн руб.",
    "млрд руб.",
    "Примечания (",
    # ...
]
```

Плюс фильтр по длине: строки короче 30 символов без буллета — почти всегда подписи к осям графиков.

### Итерация 3: выброс целых страниц

Страницы «Примечания» и глоссарий (список аббревиатур ББЛ, БУЛ, ДКП...) — бесполезны для RAG. Определяются по маркерам в первых 500 символах страницы. Из 242 начальных чанков осталось 182 — выброшено 60 страниц мусора.

Результат: точность поиска выросла с 0.48 до 0.73 только за счет чистки чанков.

Практический совет: перед написанием чанкера — обязательно вручную посмотреть 5–10 страниц из разных PDF:

```python
from pypdf import PdfReader
reader = PdfReader("data/raw/razv_bs_26_03.pdf")
print(reader.pages[4].extract_text()[:1000])
```

Без этого все предположения о структуре данных — гадание.

## Поиск: двухэтапная схема с русским re-ranker'ом

### Проблема: косинусная близость промахивается

Вопрос «Как менялись вклады населения» — косинусная близость находит страницы про «ликвидные активы» вместо «средства физлиц». Для эмбеддинг-модели все про «деньги + люди + банки» — похоже.

### Решение: русский cross-encoder

Двухэтапная схема: Qdrant достает 20 кандидатов → `DiTy/cross-encoder-russian-msmarco` (на основе DeepPavlov/rubert-base-cased) попарно сравнивает каждый с вопросом → выбирает лучшие 5.

Ключевой момент: изначально стоял английский re-ranker (`ms-marco-MiniLM-L-6-v2`, 80 МБ). Он поднял precision, но не понимал русские синонимы. Замена на русский re-ranker решила проблему — «вклады населения» = «средства физлиц» стало очевидно для модели.

## Corrective RAG: верификация через YandexGPT

Паттерн 2026 года. Стандартный RAG: вопрос → поиск → генерация → ответ. Corrective RAG добавляет шаг: вопрос → поиск → генерация → **верификация** → ответ.

### Проблема, которую решает

GigaChat получал помесячные данные по ипотеке (0,3% в мае, 1,2% в октябре) и самостоятельно вычислял годовой итог: «4,5 трлн за год, на 10% меньше 2024 года». Эта цифра отсутствовала в контексте — чистая галлюцинация. Промпт с правилом «НЕ вычисляй итоги» не помогал — модель игнорировала инструкцию.

### Решение

После генерации ответ GigaChat отправляется в YandexGPT с контекстом и промптом: «Проверь каждое фактическое утверждение. Если цифра НЕ присутствует дословно в контексте — удали утверждение».

```python
verified_answer = verify_answer(answer, context)
# answer: "4,5 трлн за год..." → verified_answer: без этой цифры
```

Результат: faithfulness вырос с 0.69 до 0.80. Галлюцинация с «4,5 трлн» исчезла из ответов.

Почему именно другая модель, а не та же? Эффект самоподтверждения — модель склонна подтверждать свои же ответы. Независимый верификатор этого недостатка лишен.

## Генерация: промпт с 9 правилами

Системный промпт — второй по важности компонент после чанкинга. Девять правил, каждое закрывает конкретную проблему:

1. Отвечать ТОЛЬКО на основе фрагментов → закрывает галлюцинации
2. Указывать источник [файл, стр. N] → верифицируемость
3. Нет информации — честный отказ → лучше, чем выдумка
4. Точные цифры, не округлять → «0,4 трлн руб.», не «около 0,4»
5. НЕ вычислять итоги, НЕ суммировать → запрет на «творческую бухгалтерию»
6. НЕ делать выводов, которых нет в тексте → запрет на интерпретации
7. Самопроверка перед каждой цифрой → механизм самопроверки
8. Русский язык, профессиональный тон → формат для исследователей
9. Данные из разных месяцев — отдельно с источниками → не путать периоды

`temperature=0.1` — почти без креатива. RAG нужны факты, не литература.

## Фолбеки: три сценария отказа

**Оценка релевантности ниже 0.5** — в базе нет данных по теме. Токены на GigaChat не тратятся, система сразу отвечает «нет данных». Но есть нюанс: вопрос «Какая погода завтра?» получил оценку 0.55 — выше порога. Система все равно ответила корректно благодаря правилу №3 в промпте. Два рубежа защиты лучше одного.

**GigaChat лежит** — retry 2 раза с паузой 3 секунды. Если все равно не отвечает — показываются сырые чанки.

**Вопрос не по теме** — промпт защищает. GigaChat говорит «в отчетах ЦБ нет данных о погоде» вместо галлюцинации.

## Эвалуация: GigaChat генерирует, YandexGPT судит

Три метрики, тест-сет из 15 вопросов (11 в рамках корпуса, 4 вне темы).

### Финальные метрики (вопросы в рамках корпуса)

| Метрика | Значение | Что измеряет |
|---------|---------|-------------|
| Достоверность (Faithfulness) | **0.80** | Доля утверждений, подтвержденных контекстом |
| Релевантность ответа (Relevancy) | **0.86** | Насколько ответ соответствует вопросу |
| Точность поиска (Context Precision) | **0.73** | Доля найденных чанков из правильных источников |
| Хорошие ответы | **9 из 11** | Вопросы с faithfulness ≥ 0.7 |

### Что дало рост

| Улучшение | Эффект |
|-----------|--------|
| Чистка чанков (глоссарий, примечания, подписи) | Precision: 0.48 → 0.73 (+52%) |
| Русский re-ranker | Корректный поиск синонимов |
| Самопроверка в промпте + верификация ответа | Достоверность: 0.69 → 0.80 (+16%) |

### Нюанс: калибровка судьи

Достоверность при первом прогоне — 0.41. После анализа — проблема в промпте YandexGPT-судьи: модель интерпретировала «подтверждается контекстом» буквально, считая «0,4 трлн руб.» и «0.4 трлн рублей» несовпадением.

Три изменения в промпте судьи:
1. «Сравнивай СМЫСЛ, а не буквальное совпадение» — фикс для разных форматов чисел
2. «Честный отказ "данных нет" = faithfulness 1.0» — система не врет, это хорошо
3. Контекст для судьи расширен с 3 000 до 6 000 символов — ключевые цифры не обрезались

Вывод: **LLM-as-judge тоже надо калибровать, иначе метрики врут.**

Дисперсия между прогонами — ±0.15. Для надежной оценки — усреднение по 3–5 прогонам.

## Железо: 8 ГБ RAM, и это не приговор

Весь прототип собран на MacBook M1 с 8 ГБ RAM. Ограничения формировали архитектуру:

- Qdrant в локальный режим вместо Docker — экономия ~500 МБ
- LaBSE-ru-turbo (500 МБ) вместо bge-m3 (2.2 ГБ) — в 4 раза легче
- Батчи по 16 при эмбеддинге — не забивать память целиком
- GigaChat через API вместо локальной модели — 7B на 8 ГБ свопит и генерирует 5 токенов/сек

Практический совет: `TRANSFORMERS_OFFLINE=1` перед запуском скриптов — модели не лезут в интернет проверять обновления. Экономит 5–10 секунд на каждом запуске.

## Что дальше

**Гибридный поиск** — BM25 + вектор. Вопрос «ключевая ставка» не находится по эмбеддингу, но нашелся бы по точному совпадению слов.

**Семантическое разбиение** — разбивка не по страницам, а по смысловым блокам. Анализ структуры страницы вместо pypdf решит проблему мусора от графиков.

**Расширение корпуса** — пресс-релизы ЦБ о решениях по ставке, обзоры финансовой стабильности, доклады о ДКП.

**Локальное развертывание** — весь стек open-source или российский. Qdrant готов к локальному развертыванию, эмбеддинг работает офлайн, GigaChat заменяется на локальную модель. Для банков и финансовых организаций — никаких внешних зависимостей.

## Итого

RAG-пайплайн: скрейпинг → чанкинг → эмбеддинг → русский re-ranker → GigaChat → Corrective RAG (YandexGPT верификация) → Gradio-демо → перекрестная оценка моделями. 182 чанка из 12 отчетов ЦБ. Достоверность 0.80, релевантность 0.86, точность поиска 0.73. 9 из 11 вопросов — хорошие ответы. Все в российском периметре, на машине с 8 ГБ RAM.

Ресерч-база не должна лежать мертвым грузом. Она может отвечать на вопросы.
